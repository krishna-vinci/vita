The constitution

Philosophy

Fixed design commitments. Changing one needs a written decision, not a quiet code change. Numbered so issues and pull requests can cite them.

1Truth over polish

A modest true line beats an impressive false one. Vita never invents an employer, skill, number or outcome.

2Every claim has a receipt

Each line links to evidence: code, a document, a link, a measurement, or something you said, with the date you said it.

3Ask, don't guess

When a line could be stronger with a fact Vita doesn't have, it asks you. Your answer is saved and reused.

4Facts once, resumes many

Your outline and project inventory are the single source of truth. A master resume and targeted base resumes grow from them, and every job resume starts from the closest base. Fix a fact once and it flows down.

5Impact over activity

Lines say what changed because of your work, not only what you did. Measured when possible, concrete always.

6The writer never grades itself

A separate checker, on a different model, reviews every line against evidence. Rate limits never collapse the two onto one model.

7Rules live in code

Anything mechanical, such as unsourced numbers, banned phrases, page count or PDF readability, is checked by code, not requested in a prompt.

8Sound like a person

No "spearheaded", no "leveraged synergies", no three-adjective stacks. Plain verbs, real nouns, varied rhythm.

9Simple surface, deep core

The default screen needs no explanation. Detail and control are available in layers, and nothing advanced is required to start.

10Agents propose, you decide

Profile changes arrive as diffs. Your own edits are locked and survive any regeneration.

11Gaps are preparation, not lies

A requirement you don't meet stays off the resume and becomes interview prep: how to answer honestly and bridge from what you know.

12Readable by people and machines

Every PDF is compiled, its text extracted and checked for reading order, so application systems parse what recruiters see.

13Your files, your models

Plain Markdown and YAML in a git repo you own. Any model provider, including local ones. Deleting the app deletes nothing.

14Extend with data, not code

Professions, templates, rules and instructions are files. Adding a career or a house style never needs an engine change.

15Cost is visible

Every run shows an estimate before and actual spend after, per role, in detailed view.

16Untrusted input stays data

Job posts, web pages and repositories are read as material, never followed as instructions.

Principles 1, 5, 8

The writing standard

Every line follows action, scope, outcome. When a real measurement exists, the line takes the XYZ form: accomplished X, measured by Y, by doing Z. When it doesn't, the writer uses the strongest outcome the evidence supports.

Outcome strengthExampleWhere it can come from
MeasuredCut chapter drafting from 9 to 3 minutesBenchmarks, logs, analytics, or a number you gave, dated
CountedIngests five source formats through one pipelineCode or documentation, with a file reference
ConcreteReplaced manual server setup with one-command rolloutsCode or documentation
Not allowedImproved efficiency by 40%Nothing. Code blocks export until it's fixed.

Metric interview

Vita notices which projects lack measured results and asks a few specific questions, chosen by profession: deploy time for DevOps, page load for frontend, data volume for data work.

No vanity numbers

Lines of code, commit counts and stars are skipped by default. Counts of real things, such as services, users, formats or latency, come first.

Human voice

Banned phrase lists, varied openings, one to two lines per bullet, and your own past wording used as a style sample.

Principles 6, 7, 12

How a resume is made

Each step is an AI role with its own model, tools and write permissions, or plain code where a rule can be checked mechanically.

analystRead the jobMust-haves, nice-to-haves, keywords. Picks the closest base resume.
selectorPick evidenceSearch your profile, keep the most relevant facts.
writerDraftStructured resume. Each line keeps links to its evidence.
codeLintUnsourced numbers, banned phrases, length, your rules.
checkerVerifyDifferent model. Reads evidence only. Flags overstatement.
ats reviewer + codeRender and parseKeywords, compile PDF, extract text, check order and pages.
youApproveAnswer what's left, edit, download. Saved to history.
notes return to the writer · at most two rounds · anything left becomes a question for you
AI rolecodereview gate

Done means

  • No number without a source
  • No open checker note, unless you overrode it, with the reason recorded
  • Every must-have is covered or listed as a gap
  • PDF compiles, fits the page limit, extracts in reading order
  • Your rules pass

Then, automatically

  • Interview prep: questions, story drafts, talking points, gap answers
  • Facts you supplied during the run are offered back to your profile
  • The application is committed, so every version you sent is recoverable
Principle 10

Editing

The resume is one structured document with an ID on every line. Clicks, chat and reviewers all make the same small changes to it, so they mix freely and every change can be undone.

WayDepthWhat it does
Click and typeSimpleEdit any line, drag to reorder, hide or add items from your profile. Edited lines are locked so regeneration never overwrites them.
ChatSimple"Fit one page", "move Skills up", "focus Kite Algo on Go". Changes only the lines involved and shows what moved.
Line actionsDetailedShorter, stronger verb, add a job keyword, swap to another wording stored in your profile.
LayoutAdvancedFont size, margins, spacing, section order, within ranges the template allows. "Fit one page" tries these before cutting content.
Raw LaTeXAdvancedDetach one application's source and edit it by hand. Vita warns that later regenerations won't touch it.

Edits that add an unsupported number or skill are flagged, not blocked: save it to your profile as your own statement, add a source, or keep it for this resume only. The choice is recorded.

Principle 4 in practice

Outline, master, base, job

Four layers, each with one job. Writing stays free at the top, rigour grows as you move down, and each layer is narrower than the one above it. Doing this by hand works but drifts: layers fall out of sync and claims go unchecked. Vita keeps the layers and removes the drift.

Source · you writeOutline + evidenceOne long, unfiltered outline in your own words, and a verified inventory: stack, evidence links, what you may and may not claim, bullet variants.Vita adds: GitHub research, metric questions, claim IDs kept invisibly
Master · broadMaster resumeThe complete best version, up to two pages. Useful on its own, and the root of every other resume.Vita adds: regenerated from the source, your polish locked
Base · per directionTargeted basesOne per career direction you pursue. Each selects and orders from the master, usually one page.Vita adds: suggested from your evidence, profession packs
Job · per applicationJob resumeStarts from the closest base, tailored to one job, checked, with interview prep.Vita adds: base picked for you, checker, PDF, history

Changes flow down

Edit the outline and Vita proposes the matching changes to the master and the affected bases as diffs. Nothing below is rewritten without your approval.

Good edits flow up

A better wording you write in a job resume can be promoted to the base, the master or the project's bullet variants, so the next resume starts from it.

Edits are kept

Lines you polished by hand in the master or a base are locked. Regenerating from the outline never overwrites them; it only suggests.

Picking the base for a job is automatic: the analyst compares the job with each base and suggests the closest, and you can switch with one click. With no targeted bases yet, the master is the starting point.

Principle 14

Extending without code

Nothing about a profession is hard-coded. IT ships first; other careers arrive as new packs. Packs give the writer and checker profession knowledge; base resumes give them your direction.

Delivery

Roadmap

The engine is built strict from day one. The surface grows in layers. Your current resume repo is the first real dataset at every step.

M0
Foundation

Outline, evidence and resume formats; importer for existing Markdown and old resumes; master resume generation; template placeholders, Rover templates converted, PDF build and text check.

M1
Strict engine, headless

Analyst, writer, checker, ATS reviewer and lint as a command-line run, with the done criteria enforced and tests on recorded model output.

M2
Simple surface

Me (outline, projects, base resumes), Jobs, Settings. Paste, question, resume with chat, click to edit, undo, download.

M3
Detailed layer and profile intelligence

Show details, profile chat with diffs, GitHub research, metric interview, interview prep.

M4
Advanced layer

Models per role, base resume suggestions and sync, IT packs, instructions, rules, layout ranges, template upload.

M5
Open-source release

Docker image, sample profile, docs, guides for contributing packs and templates, licence review.

Later
Beyond

Optional classifier, careers beyond IT, cover letters, multiple profiles per deployment.
