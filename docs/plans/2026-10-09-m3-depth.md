Rules: every story `action` cites claim ids; `result` is null unless a measured/counted metric or claim text supports it (no invented outcomes); gap answers say "no" plainly before bridging (principle 11); company notes only from the job text and allowed URLs (none fetched in M3). Routes: `POST /api/applications/:id/prep` (job), `GET /api/applications/:id/prep`. Skill `skills/interview-prep/SKILL.md` (profession-neutral, ≤ 120 lines). Tests: faux happy path; invented result rejected by a post-check (result text with a number not in claims → set to null and flagged).

### Task 2: Template upload and adoption (`core/src/templates/`, `server/src/routes/templates.ts`, `skills/adopt-template`)

```ts
export interface UploadedTemplate { id: string; dir: string; mainFile: string; files: string[] }   // stored under templates/.incoming/<id>/
export async function receiveTemplateUpload(root: string, input: { filename: string; bytes: Uint8Array }): Promise<UploadedTemplate>;
// .tex or .zip; max 10 MB; zip entries: regular files only, no absolute paths, no "..", no symlinks, max 200 entries, allowed extensions
// .tex .cls .sty .bst .bib .cfg .def .ttf .otf .png .jpg .pdf .eps; main file = the only .tex with \documentclass (else typed error)
export async function compileOriginal(upload: UploadedTemplate): Promise<{ pdf: Buffer; log: string }>;   // sandbox per spec §11.3; prescan first
export interface AdoptionProposal { id: string; templateYaml: string; mainTexNjk: string; notes: string[] }
export async function proposeAdoption(ws: WorkspaceHandle, uploadId: string, deps: PipelineDeps): Promise<AdoptionProposal>;
// role "template-adopter": reads the main file and lists other files; submit tool `submit_template` → { templateYaml, mainTexNjk, notes }; validates TemplateMeta,
// nbconvert delimiters, prescan clean, layout code preserved (proposal must keep every \usepackage/\newcommand line of the original), then renders with the
// workspace master resume (or fixtures sample when absent) and compiles; failures go back to the role once with the log
export async function approveTemplate(root: string, uploadId: string, proposal: AdoptionProposal): Promise<{ templateId: string; sha: string | null }>;
// moves to templates/<slug>/ (error if exists), writes files, deletes .incoming entry, commits as "user"
```
Routes: `POST /api/templates/upload` (multipart), `POST /api/templates/:uploadId/propose` (job), `GET /api/templates/:uploadId` (original PDF url + proposal + preview PDF url), `POST /api/templates/:uploadId/approve`, `DELETE /api/templates/:uploadId`, `GET /api/templates` (bundled + workspace, with preview availability). Before compiling an uploaded template, run `warmTemplateCache`-style trusted warm-up ONLY for packages named in its `\usepackage` lines that exist in the Tectonic bundle (run `tectonic -X compile` on a generated stub that only loads those packages, without `--only-cached`); never compile the user's file itself without `--untrusted --only-cached`. Tests: zip traversal rejected; symlink rejected; prescan blocks `\write18`; faux adoption of a fixture template (`core/src/templates/fixtures/simple-cv.tex`, fictional) compiles; approve writes and commits.

### Task 4: Fit to page (`core/src/fit/`)

```ts
export interface FitPlan { layout: Record<string, number>; hide: string[]; pages: number; fits: boolean; steps: string[] }
export async function fitToPage(resume: Resume, tpl: LoadedTemplate, opts: { maxPages: number; relevance?: Map<string, number>; signal?: AbortSignal }): Promise<FitPlan>;
// order: line_spread → section_gap_pt → margin_in → font_pt, each stepped toward its knob min in 4 steps, re-rendering + counting pages each time (stop early when it fits);
// then hide unlocked bullets with lowest relevance (default: last bullets of the longest items first) one at a time until it fits; never hides locked bullets; returns the plan without applying it
```
Route: `POST /api/:scope/:id/fit` (`scope` resumes|applications) returns the plan as `ResumeOp[]` (layout.set + bullet.hide) for the UI to preview/apply. Tests: a 2-page fixture fits via layout only; a longer one needs hides; locked bullets never hidden.
