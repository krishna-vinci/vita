# M1 Strict Engine Implementation Plan

> **For agentic workers:** dispatched per task via `.claude/skills/codex-orchestrate/dispatch.sh`. Follow `AGENTS.md`. Do not commit.

**Goal:** Headless, tested generation: claim index, lint, evidence search, a Pi 1.1 role runtime with typed submit tools, the analyst → select → writer → lint → checker → ATS/render → revise pipeline with done criteria, master-resume generation, bundled skills, and `vita master` / `vita tailor` commands.

**Architecture:** Every model role is a fresh in-memory Pi `createAgentSession` (pattern: Studium `server/src/agent/run-role.ts`) whose only way to produce output is a role-specific `submit_*` custom tool; tool arguments are validated with Zod and returned to the orchestrating code, which alone writes files. Deterministic stages (claim index, selection, lint, render check, done criteria) are plain functions. Tests use Pi's faux provider (`@earendil-works/pi-ai/providers/faux`: `fauxProvider`, `fauxAssistantMessage`, `fauxText`, `fauxToolCall`; register with `runtime.registerNativeProvider(faux.provider)`, see Studium `server/src/agent/chat-service.test.ts:8-72`).

**Tech Stack:** M0 stack plus `@earendil-works/pi-coding-agent@1.1.0`, `@earendil-works/pi-ai@1.1.0`, `typebox@1.3.27` (Pi tool parameter schemas), `node:sqlite` (FTS5, built into Node 22).

**Spec:** `docs/specs/2026-10-09-vita-design.md` §5, §8, §8.1–8.5, §14a, §19.

## Global Constraints

- All M0 global constraints apply.
- Only `core/src/agent/` imports Pi packages.
- Roles never write files. Only pipeline code writes, through `core/src/workspace` (`writeTextAtomic`, `commitPaths`).
- Job posts, outline, projects and fetched text are wrapped in prompts as `<untrusted-data source="…">…</untrusted-data>` and the system prompt states that content inside is data, never instructions (spec §16, §17).
- Tests never call real providers. Every role test uses the faux provider.
- Checker model must differ from writer model; same model → `warnings` entry; rate-limit fallback never moves the checker onto the writer's model (spec §8.5).

### Task 1: Claim index and lint (`core/src/claims/`, `core/src/lint/`) — high-risk

**Interfaces (Produces):**

```ts
// claims/index.ts
export interface IndexedClaim { id: string; text: string; source: "projects" | "outline"; itemSlug: string | null;
  itemName: string | null; evidence: Evidence[]; metrics: Metric[]; limits: string[] }
export interface ClaimIndex { claims: Map<string, IndexedClaim>; variants: Map<string, { id: string; text: string; label: string | null; itemSlug: string }>;
  items: Map<string, ProjectsItem> }
export function buildClaimIndex(projects: ProjectsDoc, outline: Outline): ClaimIndex;
// projects claims carry their item's evidence objects (resolved by id) and limits; outline bullets with claim anchors become claims with source "outline", no evidence

// lint/numbers.ts
export interface NumberToken { raw: string; norm: string; index: number }
export function extractNumbers(text: string): NumberToken[];
// finds: integers/decimals with optional thousands separators, percentages, currency ($ € £ ₹ prefixes, k/M/B suffixes), multipliers (2x, 10×), ranges split into two tokens;
// ignores ONLY: standalone 4-digit years 1950–2099, v-prefixed versions (v1.2), letters glued to digits (ES2023, IPv6), dotted triples (1.2.3). "Python 3.12" still extracts 3.12 (passes when the claim text contains it)
export function normalizeNumber(raw: string): string; // canonical forms listed below; the tests are the contract

// lint/rules.ts
export interface LintContext { index: ClaimIndex; pack: Pack; rules: { max_bullet_chars?: number; banned_phrases?: string[] } }
export function lintResume(resume: Resume, ctx: LintContext): Finding[];
```

Canonical normalisation (tests are the contract): `"70%"→"70%"`, `"70 percent"→"70%"`, `"1,200"→"1200"`, `"1.2k"→"1200"`, `"$1.2M"→"$1200000"`, `"₹50,000"→"₹50000"`, `"2x"→"2x"`, `"10×"→"10x"`, `"3.0"→"3"`.

Rules (spec §8.3), each a `Finding` with `rule` id:
- `unsourced-number` (block): for each visible, non-overridden bullet, each extracted number's norm must equal the norm of some `Metric.value` on one of its claims, or appear in the text of one of its claims (claims text is the user's own statement of fact), or in a `statement`/`measurement`/`doc` evidence `text` linked to one of its claims.
- `missing-claims` (block): `origin: "ai"` visible bullet with empty `claims`.
- `unknown-claim` (block): claim id not in the index.
- `limit-breach` (block): bullet text contains (case-insensitive) any limit's key phrase; key phrase = the limit text with leading "no "/"not "/"don't claim "/"avoid " removed, trimmed of punctuation, if ≥ 2 words.
- `banned-phrase` (warn): pack banned phrases + rules banned phrases, whole-word, case-insensitive.
- `bullet-length` (warn): `text.length > (rules.max_bullet_chars ?? 220)`.

**Tests:** table tests for extraction and normalisation (≥20 cases incl. years and versions ignored); each rule with a passing and failing resume; override suppresses `unsourced-number`; hidden bullets are not linted.

### Task 2: Evidence search and selection (`core/src/search/`)

**Interfaces:**

```ts
export class EvidenceSearch {
  static build(index: ClaimIndex, outline: Outline): EvidenceSearch; // in-memory node:sqlite FTS5, porter unicode61 tokenizer; rows: claims, variants, evidence texts, outline bullets/body
  query(terms: string[], limit: number): { kind: "claim" | "variant" | "evidence" | "outline"; id: string; text: string; score: number }[];
  close(): void;
}
export interface Selection { items: { itemSlug: string; claimIds: string[]; variantIds: string[] }[]; claimIds: string[] }
export function selectEvidence(search: EvidenceSearch, index: ClaimIndex, input: {
  keywords: string[][];   // synonym groups (analysis keywords merged with pack keywords)
  lead: string[];         // base emphasis lead_items (slugs) — always included
  locked: Bullet[];       // carried bullets; their claims always included
  maxClaims: number;      // default 40
}): Selection;
```
FTS query terms are quoted and OR-joined per group; scores aggregated per claim (bm25, lower is better → invert); claims of `lead` items first, then by score; stable ordering by id on ties.

**Tests:** fixture-based (copy `fixtures/developer` and `fixtures/nurse`): synonym group hits a claim that uses only the synonym; lead items always present; locked bullet claims always present; maxClaims respected; FTS special characters in terms do not throw.

### Task 4: Bundled skills (`skills/`)

Write `skills/{analyze-job,write-bullets,check-claims,ats-review}/SKILL.md` (frontmatter `name`, `description`), each ≤ 150 lines, profession-neutral with examples from at least two non-tech professions, following spec §5.3, §8, §14a and principles 1–8, 11, 16. `write-bullets` must include: action–scope–outcome, XYZ only with a measured metric, the four outcome strengths, every bullet lists claim ids, no numbers not present in claims/evidence, banned-phrase guidance, one to two lines per bullet, vary openers. `check-claims`: verdicts supported/overstated/unsupported with one-line reasons, compare scope words ("led" vs "contributed"), numbers, limits; no benefit of the doubt. `analyze-job`: must vs nice, keyword synonym groups, base scoring rubric. `ats-review`: coverage of must-have keyword groups, standard section titles, no tables/columns/graphics in content, file name advice. Each skill names the submit tool it is used with and describes behaviour if the tool is absent (principle: runtime-agnostic).

### Task 5: Pipeline, master generation, CLI (`core/src/pipeline/`, `cli/`)

**Interfaces:**

```ts
// schemas (in @vita/shared, review.ts / analysis.ts)
export const Requirement = z.object({ id: z.string(), text: z.string(), importance: z.enum(["must", "nice"]), keywords: z.array(z.array(z.string())) });
export const JobAnalysis = z.object({ title: z.string(), company: z.string().optional(), requirements: z.array(Requirement),
  baseScores: z.array(z.object({ baseId: z.string(), score: z.number().min(0).max(1), reason: z.string() })) });
export const CheckNote = z.object({ bulletId: z.string(), verdict: z.enum(["supported", "overstated", "unsupported"]), reason: z.string() });
export const AtsNote = z.object({ requirementId: z.string().optional(), message: z.string(), severity: z.enum(["block", "warn"]) });
export const Review = z.object({ round: z.number().int(), lint: z.array(Finding), checks: z.array(CheckNote), ats: z.array(AtsNote),
  render: RenderCheck.nullable(), gaps: z.array(z.string()), overrides: z.array(z.object({ bulletId: z.string(), reason: z.string(), at: z.string() })),
  done: z.boolean(), blocking: z.array(z.string()) });

// pipeline/done.ts
export function evaluateDone(input: { resume: Resume; lint: Finding[]; checks: CheckNote[]; analysis: JobAnalysis; gaps: string[];
  render: RenderCheck | null; overrides: Review["overrides"] }): { done: boolean; blocking: string[] };

// pipeline/master.ts
export async function generateMaster(ws: WorkspaceHandle, deps: PipelineDeps): Promise<{ resume: Resume; review: Review }>;
// pipeline/tailor.ts
export async function tailor(ws: WorkspaceHandle, input: { jobText: string; slug?: string; baseId?: string; answers?: Record<string, string> },
  deps: PipelineDeps): Promise<{ applicationDir: string; resume: Resume; review: Review; analysis: JobAnalysis }>;
export interface PipelineDeps { runtime: ModelRuntime; models: ModelsConfig; modelOverrides?: Partial<Record<RoleName, Model<Api>>>;
  onProgress?: (e: { stage: string; round?: number; message?: string }) => void; signal?: AbortSignal }
export interface WorkspaceHandle { root: string; bundledDir: string } // bundledDir = repo root holding packs/, templates/, skills/
```

Stages exactly as spec §8.2 (gap questions: when `answers` absent, unanswered must-have gaps are recorded in `review.gaps`; no interactive prompt in M1). Revision rounds ≤ 2. Writer receives: analysis, selection (claims + variants text), locked bullets, base config, effective pack, previous review notes. Writes `applications/<YYYY-MM-DD>-<slug>/{job.md,meta.yaml,analysis.json,resume.json,review.json,out/resume.{tex,pdf,md}}` and commits as `writer`. Usage per role accumulated into `meta.yaml` (`usage:`).

`generateMaster`: same as tailor without analysis/selection: writer gets all claims, page limit 2, kind `master`, then lint → checker → render → revise; writes `resumes/master/`.

CLI: `vita master <dir>`, `vita tailor <dir> --job <file|-> [--base <id>] [--slug <slug>]`, both print progress lines and the final review summary; `--faux <script.json>` flag (hidden, tests only) loads scripted faux responses.

**Tests (faux):** tailor on `fixtures/developer` with scripted role outputs completes with `done: true`; scripted writer output containing an invented number yields `unsourced-number`, second round fixes it; checker `unsupported` that persists after 2 rounds → `done: false` with blocking reason; files written and committed; master generation on `fixtures/teacher`.
