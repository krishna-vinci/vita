# M2 App Implementation Plan (server + web)

> Dispatched per task via `scripts/agents/dispatch.sh` (Codex) or the frontend agent (frontend agent). Follow `AGENTS.md`. Do not commit.

**Goal:** A usable local web app: Me (outline, projects, base resumes), Jobs (paste → gap questions → checked resume with click-to-edit and chat → export), Settings (model, key status, template), backed by a Hono API with jobs and SSE over the M0/M1 engine.

**Architecture:** `core/src/ops` applies typed edit operations to `resume.json` (one module for UI, chat and pipeline). `server/` is a Hono app holding one workspace runtime (root from `VITA_WORKSPACE`, default `./vita-data`), an in-process job runner and an SSE event hub (Studium `server/src/events.ts`, `jobs/`, `routes/events.ts` patterns). API DTOs live in `shared/src/api.ts` so server and web share types. `web/` is React 19 + Vite + Tailwind 4 + **shadcn/ui** + TanStack Query + react-router, scaffolded by Codex; critical screens are built by frontend agent.

**Tech Stack additions:** server: `hono@^4.13.10`, `@hono/node-server@^2.1.1`. web: `react@^19.3.0`, `react-dom@^19.3.0`, `react-router-dom@^7.18.0`, `@tanstack/react-query@^5.104.0`, `tailwindcss@^4.2.4`, `@tailwindcss/vite`, `vite`, `@vitejs/plugin-react`, shadcn/ui (CLI-generated components in `web/src/components/ui`, `class-variance-authority`, `clsx`, `tailwind-merge`, `lucide-react`), `sonner` (toasts), `vitest` + `@testing-library/react` + `jsdom`. Exact versions: use those already in Studium `web/package.json` where listed; otherwise latest stable at least two weeks old, pinned with `^`.

**Spec:** §4, §9, §10, §15, §16, §17. **Visual reference:** `docs/design/vita-draft.html` (v0.5 sketch: three places, job flow, Show details toggle, soft highlights with three choices).

## Global Constraints

- Server binds `127.0.0.1` by default; `VITA_HOST` other than loopback requires `VITA_PASSWORD_HASH` (scrypt) or the server refuses to start.
- All workspace writes go through `core` (`writeTextAtomic`, `commitPaths`, ops). Routes never touch the filesystem directly.
- Every mutating route returns the new resource and the commit sha; undo = `POST /api/undo` (reverts last commit) scoped to the resource's files.
- Web: shadcn/ui components only for primitives (Button, Dialog, Sheet, Tabs, Textarea, Input, Select, Switch, Toast via sonner, Tooltip, DropdownMenu, ScrollArea, Separator, Badge, Card sparingly). No other UI kit.
- Web must work at 390 px and 1440 px, light and dark. Plain language in UI copy; no internal terms (claim id, lint, tier) outside "Show details".
- Job posts and fetched text rendered in the web app as plain text only (no HTML injection).

### Task 1: Resume ops (`core/src/ops/`)

```ts
export type ResumeOp =
  | { op: "bullet.edit"; id: string; text: string }
  | { op: "bullet.add"; itemId: string; index?: number; text?: string; claimId?: string; variantId?: string }
  | { op: "bullet.hide"; id: string; hidden: boolean }
  | { op: "bullet.lock"; id: string; locked: boolean }
  | { op: "move"; id: string; toParent: string; index: number }   // bullet → item, item → section, section → resume ("root")
  | { op: "section.rename"; id: string; title: string }
  | { op: "item.hide"; id: string; hidden: boolean }
  | { op: "section.hide"; id: string; hidden: boolean }
  | { op: "layout.set"; key: string; value: number | string }
  | { op: "variant.swap"; bulletId: string; variantId: string }
  | { op: "bullet.override"; id: string; reason: "user-attested" | "this-resume-only"; note?: string };
export interface OpContext { by: "user" | "ai"; index: ClaimIndex; template: TemplateMeta; now: () => string }
export function applyOps(resume: Resume, ops: ResumeOp[], ctx: OpContext): { resume: Resume; changedBullets: string[] };
// pure; validates every op first (unknown id → OpError, nothing applied); user edits set origin "user" + locked true;
// by "ai" may not modify locked bullets (OpError "locked"); layout.set clamps to template knobs, rejects unknown keys;
// bullet.add with claimId uses claim text, with variantId uses variant text and sets variantOf; ids generated as `b-<slug>-<n>` unique
export class OpError extends Error { code: "unknown-id" | "locked" | "invalid" }
export async function applyResumeOps(root: string, resumePath: string, ops: ResumeOp[], ctx: OpContext, author: Author):
  Promise<{ resume: Resume; sha: string | null; changedBullets: string[] }>; // read, apply, Resume.parse, write, commit
```
Tests: each op; atomic failure; locked protection for ai; clamping; id uniqueness; move across items keeps document validity.

### Task 2: Server (`server/`, `shared/src/api.ts`)

Routes (JSON; Zod-validated bodies; errors `{ error: { code, message } }`):
- `GET /api/health`
- `GET /api/workspace` → `{ name, hasOutline, resumes: ResumeSummary[], applications: ApplicationSummary[], warnings: string[] }`
- `GET/PUT /api/outline` (`{ markdown, hash }`; PUT requires `baseHash`, 409 on mismatch) · `GET/PUT /api/projects` (same) · `POST /api/projects/import-legacy` (`{ markdown }` → preview diff + `apply: boolean`)
- `GET /api/resumes` · `GET /api/resumes/:id` (resume + review + pdf url) · `POST /api/resumes/:id/ops` · `POST /api/resumes` (new base `{ name, packs }` → job)
- `POST /api/master/generate` → job
- `GET /api/applications` · `POST /api/applications` (`{ jobText, baseId?, notes? }` → job) · `GET /api/applications/:id` (job text, analysis, resume, review, gaps) · `POST /api/applications/:id/answers` (`{ answers: Record<requirementId, "yes"|"no"|string> }` → rerun job) · `POST /api/applications/:id/ops` · `POST /api/applications/:id/export` (renders + writes `out/`, refuses when review not done unless every blocking item is overridden)
- `GET /api/files/*` serves PDFs from `resumes/*/` and `applications/*/out/` only (confined)
- `POST /api/undo` (`{ scope: "resume" | "application" | "outline" | "projects", id? }`)
- `GET /api/events` SSE: `job.queued|job.progress|job.done|job.failed`, `resource.changed`
- `GET/PUT /api/settings` (models config, template default; never returns secrets; reports which providers have credentials via Pi auth)
- Static: serves `web/dist` when present.

Job runner: in-process queue, one job per workspace at a time, cancellable, records usage; progress events from pipeline `onProgress`. Tests with faux provider and a temp workspace copied from `fixtures/developer`.

### Task 4: Chat backends

Roles (M1 runtime): `resume-editor` (tools: `read_resume`, `search_evidence`, `propose_ops` submit tool returning `ResumeOp[]` + a one-line summary; ops applied with `by: "ai"`; refusal path returns text without ops) and `source-editor` (tools: `read_outline`, `read_projects`, `propose_edit` submit tool returning `{ file: "outline" | "projects"; before: string; after: string; summary }` exact-string replacement, never applied without user approval). Skills: `skills/edit-resume`, `skills/edit-source`, `skills/metric-interview`. Routes: `POST /api/chat/resume/:scope/:id` (`scope` = `application|resume`; returns `{ reply, ops, applied: boolean, sha }` — ops are applied immediately when the request is the user's chat message, per principle 10, and are undoable), `POST /api/chat/source` (returns proposal), `POST /api/chat/source/apply` (applies a proposal by exact-string replacement with baseHash check). Tests with faux provider including refusal to add an unsupported skill.

### Task 5 (frontend agent): Critical screens

Build from the visual draft and the live API:
- **New job:** paste textarea (+ optional notes), "Make my resume"; shows the suggested base with "change"; progress from SSE in plain words ("Reading the job", "Picking your best evidence", "Writing", "Checking every line", "Making the PDF").
- **Questions:** one card per must-have gap: "This job asks for X. Have you done it?" Yes (opens a short text field: where and what) / No / Skip. Submits answers.
- **Resume workspace (`/jobs/:id`):** left/center resume rendered as HTML mirroring the PDF structure; click any line to edit inline (ops `bullet.edit`); drag to reorder (ops `move`); hide/show; soft highlight for blocking findings with a popover offering the three choices (add measurement → user-attested override with note; say it without the number → chat request; remove → hide); "Show details" switch revealing evidence under each line, job match list, checker notes, cost; chat panel (desktop side, phone bottom sheet) wired to `/api/chat/resume`; Undo button; Download PDF and Markdown (export route); "Prepare me" placeholder button disabled with tooltip "Coming in the next update" until M3.
- **Me:** Outline tab with a Markdown editor (plain textarea with monospace option is acceptable for M2; CodeMirror in M3) with save + conflict handling; Projects tab listing items with claim counts, evidence and limits (read-only view + "Edit as text"); Base resumes tab with Master card (generate/regenerate), base cards, "New base resume" dialog.
- Empty states for a new workspace: "Start by writing your outline or importing an old resume".
Verify with real clicks at 390 and 1440 px, light and dark.
